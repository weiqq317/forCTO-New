## 4. 监控与告警

### 4.1 告警分级

| 级别 | 说明 | 响应时间 | 升级路径 |
| --- | --- | --- | --- |
| P1 | 生产服务中断、严重退化 | 5 分钟 | 立即通知二级、项目经理 |
| P2 | 服务性能下降但可用 | 15 分钟 | 通知二级 |
| P3 | 单节点故障、功能受限 | 2 小时 | 记录并跟踪 |
| P4 | 轻微问题或计划性工单 | 1 天 | 例会处理 |

### 4.2 关键告警

- 注册掉线（Node.js ↔ Asterisk）
- SIP 呼叫成功率 < 95%
- 媒体延迟 > 150 ms（连续 3 次）
- RTPEngine 端口利用率 > 85%
- Coze API 错误率 > 5%
- TLS 证书 30 天内过期

## 5. 应急响应流程

1. **检测**：监控或 Synthetic Call 触发告警。
2. **确认**：值班工程师核实告警真实性。
3. **分级**：依据影响确定 P 级。
4. **通知**：
   - P1：即时电话/IM 通知二级、项目经理、相关干系人。
   - P2：IM + 邮件通知。
5. **处置**：
   - 参考故障处理指南。
   - 记录操作步骤与结果。
6. **恢复确认**：验证服务恢复，关闭告警。
7. **事后复盘**：
   - P1/P2 事件需 24 小时内完成初步报告，3 个工作日内提交复盘。

## 6. 常见故障诊断指南

### 6.1 SIP 注册失败

- **症状**：监控告警、Asterisk CLI 显示分机离线。
- **排查步骤**：
  1. 检查网络连通性（ping、telnet 5060）。
  2. 查看 Node.js 日志是否有错误码（401/403）。
  3. 检查凭证是否过期。
  4. 重启 Node.js Pod（谨慎）。
- **应急措施**：
  - 启用备用节点。
  - 联系 Asterisk 团队确认配置。

### 6.2 呼叫建立失败

- **症状**：INVITE 返回 4xx/5xx，呼叫无法接通。
- **排查步骤**：
  1. 使用 sngrep 捕获 SIP 流。
  2. 检查 Node.js 日志中 Coze/RTPEngine 错误。
  3. 验证 RTPEngine `offer` 是否成功返回。
- **应急措施**：
  - 临时禁用 AI，转人工队列。

### 6.3 媒体无声/断断续续

- **症状**：客户听不到声音或音质差。
- **排查步骤**：
  1. 检查 RTPEngine 统计（丢包率、抖动）。
  2. 验证 TURN 是否启用，网络是否存在限制。
  3. 采集 RTP 抓包分析（tcpdump + Wireshark）。
- **应急措施**：
  - 切换至备用 RTPEngine 节点。
  - 启用专用 TURN 节点。

### 6.4 Coze API 超时

- **症状**：创建会话失败、时延增加。
- **排查步骤**：
  1. 查看 API 调用日志、错误码。
  2. 检查出站网络、防火墙。
  3. 咨询 Coze 平台状态。
- **应急措施**：
  - 启用备用脚本（播放提示语，稍后回拨）。

### 6.5 证书/令牌过期

- **症状**：TLS 握手失败、认证失败。
- **排查步骤**：
  1. 查看 Vault/证书管理日志。
  2. 检查自动轮换任务状态。
- **应急措施**：
  - 手动更新证书，重启相关组件。
  - 通知安全团队审计。

## 7. 维护窗口与变更流程

- **常规维护窗口**：每周二 02:00-04:00（本地时间）。
