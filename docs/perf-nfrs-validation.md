# 性能与 NFR 验证方案

本文描述如何验证端到端延迟（≤ 150 ms）、抖动（≤ 30 ms）等关键 NFR，以及并发容量目标。

## 1. 工具与指标
- SIP 负载：sipp（可模拟并发呼叫与 RTP 媒体）。
- 媒体统计：RTPEngine 统计接口/日志；Asterisk RTCP 统计；webrtc-internals（浏览器侧参考）。
- 系统观测：nodejs event loop delay、CPU、内存、PPS；Prometheus + Grafana 仪表盘。
- 网络仿真：tc/netem 注入延迟/抖动/丢包，验证抗性与回退策略。

## 2. 延迟测量
- 单通：SIP UA → Asterisk → RTPEngine → Coze → 回传 → 端到端往返时间。
- 方法：在音频流中注入标记音/序号包，在接收端回环，计算 RTT 与单向延迟估计。
- 采样：P50/P95/P99，分峰值与谷值时段采集。

## 3. 抖动与丢包
- 统计 RTCP XR/Jitter、丢包率（上行/下行）。
- 容忍阈值：抖动 ≤ 30 ms；丢包 < 1%（语音仍可接受）。

## 4. 并发与容量
- 目标 N（如 500）并发：逐步爬坡测试（50 → 100 → 200 → ...）。
- 观察：RTPEngine CPU（转码开销）、PPS、带宽；CoTURN 端口与会话耗尽；Node.js 事件循环延迟。

## 5. 失败注入
- 关闭/降级 TURN，模拟对称 NAT；验证备用 TURN 与回退策略。
- 人为更换证书/指纹失败，检验重协商与告警。

## 6. 通过准则
- 延迟：平均 ≤ 150 ms，P95 ≤ 220 ms。
- 抖动：标准差 ≤ 30 ms，峰值 ≤ 50 ms（短时）。
- 稳定性：24 小时无重大错误，自动恢复率 ≥ 99%。

- 报告：图表化展示各指标；问题项与优化建议；容量建议与成本估算。
